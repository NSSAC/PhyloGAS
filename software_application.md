### 1. Project Overview & Purpose (What it is)
* **Project Name:** PhyloGAS (PhyloGeographic Analysis Similars)
* **Project Homepage/Primary URL:** https://github.com/NSSAC/PhyloGAS/tree/main
* **Brief Summary:** A framework for benchmarking cascade reconstruction using phylogenetics.
* **Full Description:** This software provides a framework to quantify the performance of phylogenetic reconstruction methods according to observational biases in genomic surveillance. It achieves this by integrating ground-truth transmission networks from agent-based simulations with genomic cluster data. The framework explicitly models two primary sources of bias: incomplete sampling, governed by the genomic ascertainment rate, and the artificial splitting of transmission chains across geographic boundaries. By predicting how the observed distribution of transmission clusters converges toward the ground truth as sampling increases, the model enables the estimation of sampling targets required for accurate cascade reconstruction.
* **Maintainer/Contact:** Andrew Warren, Mandy Wilson
* **Date of Last Update:** 2025-07-15

### 2. Public Health Application (The Application)
* **Primary Goal:** To provide data, software, and analysis of the performance constraints of state-of-the-art phylodynamic software in the face of uncertainty quantified by a simulation. This gives public health officials the ability to benchmark the performance associated with their deployed pipelines.
* **Use Case Example:** A public health department has deployed a Nextstrain server to understand in-state transmission based on genomic surveillance. A bioinformatics technician uses this framework to test their instance against synthetic ground-truth data, allowing them to understand the performance and resolution limits of the capability they are providing.
* **Intended Impact:** This framework provides a consistent, mathematically rigorous reference point for public health departments to test their deployment and demonstrate the use of tools with non-PHI (Protected Health Information) data.

### 3. Intended Audience (Who it is for)
* **Primary Users:** Epidemiologists and decision-makers (to evaluate results and set sampling targets), and bioinformaticians (to interact with the system directly).
* **Required Skills:** Ability to configure and run software via the command line.

### 4. Expected Inputs
* **Data/Information Required:** PhyloGAS is orchestrated via a configuration file (`config.yaml`). It requires synthetic population demographics and transmission dendrograms generated by agent-based epidemiological simulations (e.g., EpiHiper).
* **Input Formats:** YAML (configuration), CSV/TSV (demographics), and network graphs/simulation logs.
* **Link to Detailed Input Specification:** Provided within the `config.template.yaml` in the GitHub repository.
* **Constraints & Limitations:** The pipeline requires high-resolution synthetic transmission networks. To reduce computational overhead and setup time, the pipeline is configured to automatically pull pre-generated foundational files from the UVA Dataverse.

### 5. Expected Outputs
* **Results Generated:** The pipeline automatically outputs: 
  1) Ground-truth synthetic genomes (FASTA) and metadata.
  2) Simulated line lists reflecting ascertainment biases.
  3) Sampled datasets subsetted via specified sampling algorithms (e.g., Simple Uniform Random Sampling).
  4) Reconstructed phylodynamic trees (Nextstrain builds).
  5) Benchmarking metrics comparing the sampled reconstruction to the ground truth.
* **Output Formats:** FASTA (genomes), CSV/TSV (line lists/metrics), JSON (Auspice/Nextstrain trees).
* **Interpreting the Output:** Output metrics (such as Mean Reciprocal Distance, Topological F1-Scores, and Cosine Similarity) quantify how accurately the sampled data reconstructs the true transmission chain, and how closely the observed distribution of transmission clusters matches reality.
* **Link to Detailed Output Schema/Data Dictionary:** See the Output Structure section of the repository README.

### 7. Instructions for Use
* **System Requirements:** Linux/Mac OS, Snakemake (≥7.0), Python (3.10/3.11).
* **Installation/Setup:** Can be deployed via Conda/Mamba (`mamba env create -f environment.yml`) or via container (`apptainer pull phylogas.sif docker://nssac/phylogas:latest`).
* **Quick Start Guide:** 
  1. Copy the configuration template: `cp config.template.yaml config.yaml`
  2. Modify target parameters (e.g., sampling algorithms, bottleneck sizes) in `config.yaml`.
  3. Execute the pipeline: `snakemake --use-conda --cores all`
* **Further Documentation:** See the full README.md in the GitHub repository for detailed pipeline architecture and configuration instructions.
