### 1. Project Overview & Purpose (What it is)
* **Project Name:** PhyloGAS (PhyloGeographic Analysis Similars). *Similars* are a modulation of the digital-twin concept: synthetic counterparts that are statistically faithful to a real population without replicating any individual.
* **Project Homepage/Primary URL:** https://github.com/NSSAC/PhyloGAS/tree/main
* **Brief Summary:** A framework for benchmarking cascade reconstruction using phylogenetics.
* **Full Description:** This software provides a framework to quantify the performance of phylogenetic reconstruction methods according to observational biases in genomic surveillance. It achieves this by integrating ground-truth transmission networks from agent-based simulations with genomic cluster data. The framework explicitly models two primary sources of bias: incomplete sampling, governed by the genomic ascertainment rate, and the artificial splitting of transmission chains across geographic boundaries. By predicting how the observed distribution of transmission clusters converges toward the ground truth as sampling increases, the model enables the estimation of sampling targets required for accurate cascade reconstruction.
  Because the ground truth is synthetic, every quantity a phylodynamic pipeline estimates -- who infected whom, where a lineage moved, how fast it evolved -- has a known answer to score against, which is not available from real surveillance data.
* **Current Status:** The end-to-end pipeline runs unattended for five states (Virginia, Massachusetts, Minnesota, Georgia, Washington) from a single command; a sixth (California) has population data staged. Each state is a self-contained study whose configuration differs from the others by two lines.
* **Maintainer/Contact:** Andrew Warren, Mandy Wilson
* **Date of Last Update:** 2026-10-09

### 2. Public Health Application (The Application)
* **Primary Goal:** To provide data, software, and analysis of the performance constraints of state-of-the-art phylodynamic software in the face of uncertainty quantified by a simulation. This gives public health officials the ability to benchmark the performance associated with their deployed pipelines.
* **Use Case Example:** A public health department has deployed a Nextstrain server to understand in-state transmission based on genomic surveillance. A bioinformatics technician uses this framework to test their instance against synthetic ground-truth data, allowing them to understand the performance and resolution limits of the capability they are providing.
* **Second Use Case -- Sampling Budgets:** A department sequences a fixed number of specimens per week and wants to know whether a different selection rule would buy more reconstruction accuracy at the same cost. The framework runs competing strategies (uniform random sampling against adaptive, CSTE-aligned methods) over the same synthetic wave and reports what each recovers, so the comparison is made before the sequencing budget is committed rather than after.
* **Intended Impact:** This framework provides a consistent, mathematically rigorous reference point for public health departments to test their deployment and demonstrate the use of tools with non-PHI (Protected Health Information) data. Because the line lists and genomes are simulated, they can be shared, published and used for training without disclosure review -- the usual barrier to distributing a realistic genomic-surveillance test set.

### 3. Intended Audience (Who it is for)
* **Primary Users:** Epidemiologists and decision-makers (to evaluate results and set sampling targets), and bioinformaticians (to interact with the system directly).
* **Required Skills:** Ability to configure and run software via the command line. No phylogenetics expertise is needed to produce a benchmark; interpreting the reconstruction metrics does assume familiarity with phylodynamic output.

### 4. Expected Inputs
* **Data/Information Required:** PhyloGAS is orchestrated via a single configuration file. It requires synthetic population demographics and transmission dendrograms generated by agent-based epidemiological simulations (e.g., EpiHiper); both are downloaded automatically. Seed genomes are not supplied by the user: the pipeline retrieves real sequences from Cov-Spectrum for the phylogenetic clusters that seeded the modelled wave, so the simulated epidemic begins from observed viral diversity rather than an invented ancestor.
* **Input Formats:** YAML (configuration), CSV/TSV (demographics), FASTA (reference and seed genomes), and network graphs/simulation logs.
* **Link to Detailed Input Specification:** Provided within the `config.template.yaml` in the GitHub repository, which is a commented reference for every setting.
* **What the User Actually Sets:** Most paths and dates are derived rather than typed. Naming the state fills in the population files, division names, simulation replicate and output locations; the simulation's calendar start is read from the agent-based model's own configuration, so a tick and its date cannot drift apart. A configuration that disagrees with itself is rejected at load time instead of producing a misaligned run.
* **Constraints & Limitations:** The pipeline requires high-resolution synthetic transmission networks; these are pulled automatically rather than built by the user. Seed retrieval and the phylogenetic stage need outbound network access, which on a restricted cluster means running the preparation step from a login node. Runs are compute-intensive: a full single-state run took 1.5-4 hours on 32 cores.

### 5. Expected Outputs
* **Results Generated:** The pipeline automatically outputs: 
  1) Ground-truth synthetic genomes (FASTA) and metadata.
  2) Simulated line lists reflecting ascertainment biases.
  3) Sampled datasets subsetted via specified sampling algorithms (uniform random sampling and adaptive strategies), one per sampling recipe.
  4) Reconstructed phylodynamic trees (Nextstrain/Auspice builds).
  5) Benchmarking metrics comparing the sampled reconstruction to the ground truth.
  6) Molecular clock estimates separating the rate the simulation actually generated from the rate the phylodynamic tool assumed.
* **Output Formats:** FASTA (genomes), CSV/TSV (line lists/metrics), JSON (Auspice/Nextstrain trees).
* **Interpreting the Output:** Mean Reciprocal Distance measures how much of the transmission tree a sample set reaches: for every infection in the simulated wave -- reported or not -- the reciprocal of one plus its distance along the true transmission tree to the nearest sequenced case, averaged. It is 1 when every infection is sequenced and falls toward 0 as infections sit further from any sample; because unreported infections count, ascertainment bias shows up in the score rather than being hidden in the denominator. It is reported cumulatively, restricted to larger transmission trees, over a rolling 8-week window, and per age group to expose inequitable coverage. Geographic reconstruction is scored on the off-diagonal entries of the inferred transition matrix against the simulation's true one, by cosine similarity (is the shape of the flow right), topological F1 (were the right county-to-county connections recovered at all), Pearson correlation (is the magnitude right) and masked mean absolute error. Separate outputs cover how closely each sample's demographic make-up matches the true infections (cumulatively and per sampling window), variant prevalence, transmission-component coverage and sequence divergence. The clock estimates are reported as distinct quantities and should not be conflated: a rate measured from the synthetic truth, a rate inferred from the tree, and the fixed rate the Nextstrain build assumed -- the last cannot support a claim about the simulation's rate, because it was an input rather than a measurement.
* **Link to Detailed Output Schema/Data Dictionary:** See the Output Structure section of the repository README.

### 7. Instructions for Use
* **System Requirements:** Linux/Mac OS, Snakemake (>=7.0), Python (3.10/3.11). A workstation suffices for a single state; an HPC allocation is recommended for several. Phylodynamic reconstruction additionally requires the Nextstrain CLI or Conda, which builds its own toolchain -- users do not install augur or nextclade themselves.
* **Installation/Setup:** Deployed via Conda/Mamba (`mamba env create -f environment.yml`). A container image is planned but not yet published.
* **Quick Start Guide:**
  1. Copy the configuration template: `cp config.template.yaml config.yaml`
  2. Set the state and any target parameters (e.g., sampling algorithms, sequencing budget) in `config.yaml`.
  3. Check readiness: `phylogas status` reports what is present, what is missing, and the single next command to run.
  4. Download inputs: `phylogas fetch-data --config config.yaml`
  5. Execute the pipeline end to end: `phylogas run --config config.yaml --cores all full`
* **Running Several States:** `scripts/make_state_configs.py` generates a configuration per state, and `slurm/` holds a batch script for each, so a multi-state benchmark is a set of independent job submissions rather than a hand-edited configuration per run.
* **Individual Stages:** Each stage is also a subcommand (`phylogas prep-seeds`, `phylogas train`, `phylogas paint`, `phylogas benchmark ...`), so a user who wants only ascertainment simulation or only the benchmark scoring can run that part against their own data.
* **Further Documentation:** See README.md in the GitHub repository for pipeline architecture and configuration; `BETA_TESTING.md` for a guided first run; `docs/clock_modes.md` for how the molecular-clock estimates differ and when each applies; and `command_map.md` for the mapping from the original research scripts to the current commands.
